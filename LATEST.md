## Точные причины и исправления

Ранее клиент сначала ждал метаданные, затем ответ на весь каталог, и только тогда показывал машины. Он получал все галерейные ссылки и создавал сотни карточек в DOM. Самих фотографий в JSON не было. Изображения уже имели отложенную загрузку; одновременная загрузка всех оригиналов не подтверждается.

Теперь первые 24 компактные карточки показываются после первой страницы, остальные данные поступают по 200 в фоне. Список содержит все поля для поиска и обложку; полная галерея запрашивается только при открытии автомобиля. DOM постепенно добавляет результаты по 24 при прокрутке. Отложенная загрузка и асинхронное декодирование фото сохранены. Прежний выбор обложки в подробностях сохранён. Изменений дизайна, кроме необходимых состояний загрузки, нет.

Ни одна машина не отбрасывается. Марки, модели, годы, комплектации и цены фильтруются по полному индексу. Если поиск выбран до его завершения, явно отображается ожидание полного каталога, а частичная выборка не выдаётся за окончательный результат. После получения всех страниц поиск применяется ко всем данным. Избранное не очищается по первой частичной странице, периодическое обновление не подменяет полный каталог её фрагментом. При обрыве неполного чтения показана ошибка.

Внешний SDK стоял перед приложением как блокирующий script. Это заставляло интерфейс ждать внешний домен. Сам двухминутный сетевой запрос на телефоне не измерен и не объявляется установленным фактом. Неизменённый официальный SDK размещён на существующем HTTPS и подключён асинхронно. Его совпадение с официальным файлом подтверждено контрольной суммой; в сети он занимает 22513 байт со сжатием, получен с сервера за 30,5 мс. Он не содержит токена бота.

Метаданные выбора обложки раньше читались и разбирались отдельно для каждой машины. Теперь неизменённый файл читается один раз с общей ожидающей операцией; изменение файла сбрасывает кэш. В отдельном сравнительном запуске построение всех публичных карточек сократилось с 991,4 до 185,4 мс.

Полный снимок кэшируется максимум 30 секунд с проверкой всех входных файлов при обращении и досрочным сбросом на сроке цены, политики или смене дня. Возвращаются изолированные копии. Переиспользуется объект форматирования даты; правила проверки цен и формулы не менялись. Для чтения фото используется существующий облегчённый снимок медиа без повторного обогащения ценами. Срок активности, происхождение, путь, формат и хеш по-прежнему проверяются.

Все оригиналы выбранной карточки проверяются до первого сообщения. Уже проверенные данные переиспользуются внутри одной операции в пределах ограниченного объёма памяти; для превышения остаётся прежнее чтение. Фото не скачиваются заново из Telegram. Это сократило локальное чтение двух исходных файлов, но не является измерением скорости реальной отправки после исправления.

## Повторные нажатия, состояния и измерения

Историческое число повторных HTTP-запросов установить нельзя: прежние журналы их не сохраняли. В существующей истории только одна успешная доставка, а не несколько подтверждённых дублей. Исправлена возможность параллельной повторной подготовки: восемь одновременных кликов в тесте дают один запрос preview и ноль отправок. Обе исходные кнопки заблокированы до завершения подготовки; во время отправки повторное подтверждение также блокируется.

Исправлен обработчик закрытия окна, который при повторном открытии мог обращаться к новому общему окну вместо закрываемого. Пользователь видит «Подготовка карточки», готовый предварительный просмотр, «Отправка характеристик», «Отправка фотографий», «Отправлено» либо конкретную ошибку. Во время доставки читается только состояние собственного запроса.

Существующие устойчивый журнал, проверка роли, одноразовый допуск, запрет повторов после неизвестного результата и лимиты Telegram сохранены. Перед каждым текстом, альбомом и одиночным фото проверяется единственный разрешённый тестовый адрес. Реальные дилерские группы категорически запрещены.

Добавлены локальные клиентские измерения интерфейса, первых карточек и первого фото, нажатия и запросов авторизации; серверные измерения подготовки, чтения оригиналов и каждого вызова Telegram. Метрики содержат фиксированные названия этапов, время и объём, без переписки, токена или подписанных данных. Новая реальная доставка не запускалась, поэтому её длительность ещё неизвестна.
